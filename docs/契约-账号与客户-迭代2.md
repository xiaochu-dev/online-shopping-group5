## 二、请求参数与模型属性

### 2.1 `POST /buyer/register`

| 参数 | 必填 | 规则 |
| --- | :-: | --- |
| `username` | 是 | 2~20 字符，全局唯一 |
| `password` | 是 | ≥ 8 位 |
| `confirmPassword` | 是 | 必须与 `password` 一致（Controller 层校验） |
| `phone` | 是 | 非空、≤ 20 字符；**不要求唯一、不校验格式**（澄清结论：电话可重复填） |
| `defaultPlace` | 否 | ≤ 100 字符 |

失败时返回注册页并带 `error`（字符串，可直接展示）；`username` / `phone` / `defaultPlace` 会回填。

### 2.2 `POST /buyer/login`

| 参数 | 必填 | 说明 |
| --- | :-: | --- |
| `username` | 是 | 用户名 |
| `password` | 是 | 明文密码 |
| `redirect` | 否 | 登录成功后的跳转地址，只接受站内绝对路径（`/` 开头且不以 `//` 开头） |

失败提示固定为「用户名或密码错误」——账号不存在与密码错误**不区分**，防用户名枚举。

### 2.3 `GET /admin/customers`

| 参数 | 缺省 | 说明 |
| --- | --- | --- |
| `keyword` | 空 | 用户名或电话模糊匹配 |
| `page` | 1 | 页码 |
| `size` | 10 | 每页条数（上限由 MyBatis-Plus 分页插件限制为 100） |

模型属性：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `pageResult` | `PageResult<Buyer>` | `records` / `total` / `page` / `size` / `totalPages` / `hasPrev` / `hasNext` |
| `keyword` | `String` | 回显检索词 |
| `totalCustomers` | `long` | 注册客户总数 |

### 2.4 `GET /admin/customers/{id}`

模型属性：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `buyer` | `Buyer` | 客户实体（**不含密码字段的展示**，模板只取 username / phone / defaultPlace / createdAt） |
| `history` | `List<IntentHistoryItem>` | 购买历史，见第四节 |
| `historyReady` | `boolean` | 当前IntentHistoryProvider已接入，为true；未注册Provider时才显示未接入提示 |

客户不存在时 302 → `/admin/customers?error=客户不存在`。

## 三、跨模块出口：`BuyerContext.current()`

**这是买家登录态的唯一对外接口。** 门户模块（周到）取当前买家的写法：

```java
@Autowired
private BuyerContext buyerContext;

Buyer buyer = buyerContext.current();   // 未登录返回 null
if (buyer == null) {
    // 页面请求：跳登录页并带回跳地址
    return "redirect:/buyer/login?redirect=" + URLEncoder.encode("/product/12", UTF_8);
}
Long buyerId = buyer.getId();
String name  = buyer.getUsername();
String phone = buyer.getPhone();               // 必填，可直接作为下单快照
String place = buyer.getDefaultPlace();        // 可能为 null，下单页让用户当次填
```

约定：

1. **不要自己读 cookie、不要直接查 `buyer` 表**——登录态实现属于本模块内部；
2. `current()` 每次请求只查一次库（结果缓存在 request attribute）；
3. 返回 `null` 表示未登录，**不要**用 `Optional` 或抛异常；
4. 供应商保证：`getId()` 非空；`getPhone()` 非空；`getDefaultPlace()` 可能为 `null`。

### 登录态存储（实现细节，仅供排查）

| 项 | 卖家 | 买家 |
| --- | --- | --- |
| 载体 | `SHOP_SESSION`（HttpSession） | `BUYER_SESSION`（签名 cookie） |
| 有效期 | 7 天 | 7 天 |
| 互影响 | 两套独立，同一浏览器可同时登录，互不踢号 | 同左 |

`BUYER_SESSION` 的值为 `buyerId:过期毫秒:HMAC-SHA256`，签名密钥每次启动随机生成。
**因此应用重启后所有买家需要重新登录**（与 HttpSession 行为一致），演示前请勿重启后直接演示下单。

## 四、待提供方实现的端口：`IntentHistoryPort`

客户详情页的「购买历史」由 portal 模块提供，接口定义在 `com.group5.shop.admin.port`：

```java
    List<IntentHistoryItem> listByBuyer(Long buyerId);
```

```java
        ...
    }
}
```

```java
// 方式 B：在 portal 的 @Configuration 里用 @Bean 提供
```

`CustomerAdminController` 通过 `ObjectProvider` 取用：**实现类一注册就自动接上**，
当前portal.IntentHistoryProvider已经注册，客户历史已接入。未注册Provider时仍有未接入提示分支；admin无需直接读intent表。

字段要求：

| 字段 | 必填 | 说明 |
| --- | :-: | --- |
| `productName` | 是 | 商品名称快照 |

| `result` | 是 | 仅 `success` / `failed` |
| `finishedAt` | 否 | 交易完成时间；未完成传 `null` |
| `failReason` | 否 | 失败原因；成功传 `null` |

## 五、错误码

本模块**未改动** `ErrorCode` 枚举（公共层本迭代冻结），复用既有码并带自定义提示语：

| 场景 | 业务码 | 提示语 |
| --- | --- | --- |
| 用户名已被注册 | 40001 `PARAM_INVALID` | 用户名已被注册，请换一个 |
| 用户名长度不合法 | 40001 | 用户名长度需在 2~20 个字符之间 |
| 密码不足 8 位 | 40104 `PASSWORD_TOO_SHORT` | 新密码长度不得少于 8 位 |
| 电话为空 | 40001 | 请填写联系电话 |
| 登录失败 | 40101 `LOGIN_FAILED` | 用户名或密码错误 |
| 未登录访问受保护资源 | 40102 `UNAUTHORIZED` | 页面 302 / 接口 401 + `请先登录买家账号` |

## 六、联调检查清单（本模块 8 项）

- [ ] `/buyer/register` 能注册，重复用户名被拒且提示明确
- [ ] 电话为空被拒；同一电话可注册两个账号
- [ ] 注册后库中 `password_hash` 不是明文、`salt` 非空
- [ ] `/buyer/login` 正确凭据下发 `BUYER_SESSION`（HttpOnly），错误凭据提示「用户名或密码错误」
- [ ] 卖家 `SHOP_SESSION` 与买家 `BUYER_SESSION` 同时存在时，两个后台都能打开
- [ ] 手改 `BUYER_SESSION` 任一字符后访问 `/buyer/me` 被拒
- [ ] 未登录访问 `/my/orders` 跳 `/buyer/login?redirect=%2Fmy%2Forders`
- [ ] 卖家后台 `/admin/customers` 能检索、能翻页、能进详情

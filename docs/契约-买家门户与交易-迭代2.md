# 买家门户与交易模块 · 接口契约（迭代 2 / T2-13 ~ T2-18）

> 维护人：周到（产品经理）　适用版本：任务表 v4.0
> 覆盖挑战需求 A.1.3（一件一单与库存）、A.1.4（售罄与队列归零）、A.2.1（下单必须登录）、
> A.2.2（同买家同商品限一条未结束意向）、A.2.5（商家确认交易与客户历史）。
> 本文件是「提供方契约」：卖家后台、商品模块按此对接，不必再问人。

---

## 一、路由一览

### 1.1 买家侧

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/` | 公开 | 商品列表，返回视图 `portal/product-list` |
| GET | `/products/{id}` | 公开 | 商品详情，返回视图 `portal/product-detail`；不存在或已下架 → 404 错误页 |
| POST | `/products/{id}/intents` | **需买家登录** | 提交购买意向；未登录 302 → `/buyer/login?redirect=/products/{id}` |
| POST | `/intents/cancel` | 公开（凭口令码） | 基线兜底：存量匿名单凭码撤销，买家页面已无入口 |
| GET | `/my/orders` | **需买家登录** | 我的订单，返回视图 `portal/my-orders`；未登录 302 回登录页 |

### 1.2 卖家侧（需卖家登录，`LoginInterceptor` 拦 `/admin/**`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/intents` | 交易与意向总览（我的商品 + 各商品未结束意向数），视图 `portal/seller-products` |
| GET | `/admin/intents/{productId}` | 单商品队列页（交易中 1 条 + 排队若干），视图 `portal/seller-intents` |
| POST | `/admin/intents/{intentId}/confirm` | 确认交易：队首 `pending → trading`，商品置 `frozen` |
| POST | `/admin/intents/{intentId}/success` | 交易成功：扣 1 件库存，单置 `success`，商品解冻回 `on_sale` |
| POST | `/admin/intents/{intentId}/fail` | 交易失败：库存不动，商品解冻，买家作废或塞回队尾 |

> 三个动作完成后统一 303 回 `/admin/intents/{productId}?msg=…`，避免 F5 重复执行。

## 二、请求参数与模型属性

### 2.1 `GET /`（商品列表）

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | int | 否 | 1 | 页码，非正数按 1 处理 |
| `size` | int | 否 | 12 | 每页条数，上限 100，超出按 100 截断 |
| `categoryId` | long | 否 | — | 一级或二级分类 id；`parent_id` 为空的是二级，父级筛选自动含子级 |
| `keyword` | string | 否 | — | 同时匹配商品名称与描述（`name LIKE %kw% OR description LIKE %kw%`） |
| `msg` / `error` | string | 否 | — | 一过性提示，由 PRG 重定向带回 |

返回模型属性：`pageResult`（含 `records`/`total`/`pageNo`/`pageSize`）、`categoryTree`、`categoryNames`、`categoryId`、`keyword`、`buyerName`、`msg`、`error`。

**排序**：`published_at DESC, id DESC`（新发布的在前）。只返回 `on_sale` 的商品。
**传了不存在的分类**：返回空结果，不退回「全部」——否则用户会以为筛选没生效。

### 2.2 `GET /products/{id}`（商品详情）

无请求参数（除 `msg` / `error`）。返回模型属性：`view`（含 `product`、图片列表、库存）、`product`、`queueSize`（当前 `pending` 条数）、`loggedIn`、`buyerName`。

- 库存：`product.stock` 未就绪时按 `null` 处理，页面显示「不限」；
- 图片：`product_image` 表未就绪时回落到 `product.image_path` 单图；
- 商品状态非 `on_sale` 时下单区显示为不可用，并说明「交易中」或「已下架」。

### 2.3 `POST /products/{id}/intents`（提交意向）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `tradeAddress` | string | 否 | 本次交易地点；留空则用买家的默认交易地点 |

- 姓名、电话取下单时的买家账号快照（`buyer_name` / `phone`），页面不重复填写；
- 成功：303 → `/products/{id}?msg=购买意向已提交，等待卖家确认。可在「我的订单」查看已有结果的订单。`
- 失败：303 → `/products/{id}?error={消息}`（不抛异常页）。

### 2.4 `GET /my/orders`（我的订单）

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | int | 否 | 1 | 页码 |
| `size` | int | 否 | 10 | 每页条数，上限 100 |

返回 `pageResult`（元素为 `OrderItem`：商品名、下单时间、结果、交易时间、失败原因）。

**口径**：只返回 `status IN ('success','failed')` 的单，按 `finished_at DESC, id DESC` 排序。
排队中、交易中的单**不出现在这里**——它们还没有结果，不算历史。

### 2.5 `GET /admin/intents/{productId}`（队列页）

返回：`product`、`activeQueue`（`pending` + `trading`，按 `created_at ASC, id ASC`）。
位次不落库，由查询时的行号算出，因此有人结束或撤销后，后面的人自动前移。

### 2.6 `POST /admin/intents/{intentId}/fail`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `requeue` | boolean | 否 | `true` = 塞回队尾（置回 `pending` 并刷新 `created_at`）；缺省或 `false` = 作废（置 `failed`） |
| `reason` | string | 否 | 失败原因，留空写「交易未达成」 |

> 塞回时会校验该买家在同一商品上是否已有另一条未结束意向；有则拒绝，提示改选「作废」，
> 避免一个人占两个队列位置。

## 三、跨模块依赖

### 3.1 本模块向外提供

| 出口 | 使用方 | 说明 |
| --- | --- | --- |
| `IntentHistoryProvider`（实现 `admin.port.IntentHistoryPort`） | 卖家后台客户详情页 | 按 `buyerId` 返回已结束订单（最多 100 条），商品名、下单时间、结果、交易时间、失败原因 |

该接口由账号与客户模块（admin）定义，本模块实现并注册为 Bean。对方用
`ObjectProvider<IntentHistoryPort>` 取用：实现到位自动接上，缺失也不启动失败。

### 3.2 本模块向内依赖

| 依赖 | 提供方 | 缺失时的行为 |
| --- | --- | --- |
| `BuyerContext.current()` | 账号与客户模块 | 必需的正式实现；未登录返回 `null`，由本模块跳登录页 |
| `ProductPort`（`freeze`/`release`/`deduct`/`stockOf`/`imagesOf`） | 商品中心（正式实现）或本模块自带适配层 | 本模块自带 `@ConditionalOnMissingBean` 默认实现：`stock` 列不存在时 `stockOf()` 返回 `null`（按「不限」），`imagesOf()` 返回空列表 |
| `CategoryPort` | 商品中心或适配层 | 适配层用 `product.category` 文本列推导两级分类 |

约定：**`intent` 表只有本模块读写**，其他模块要数据一律走上面两个接口，不直接写 SQL。

## 四、状态机

```
pending ──确认交易──→ trading ──交易成功──→ success   （扣 1 件库存）
   ↑                     │
   └──塞回队尾───────────┴──交易失败──→ failed        （库存不动）
```

| 规则 | 实现位置 |
| --- | --- |
| 只有队首能确认交易 | `SellerIntentService#confirmTrade` 校验「`pending` 队列第一条就是它」 |
| 扣库存在「交易成功」那一刻，不在提交意向时也不在确认时 | `markSuccess` → `productPort.deduct()` |
| 确认交易时商品置 `frozen`，其他买家无法下单 | `confirmTrade` → `productPort.freeze()` |
| 失败/成功后商品解冻回 `on_sale` | `markFailed` / `markSuccess` → `productPort.release()` |
| 库存扣到 0，剩下排队者批量置 `failed`（原因「商品库存已售罄…」） | `markSuccess` → `failPendingOfProduct()` |
| 没有独立的「取消」状态，卖家「取消」等于置 `failed` | 状态机只认上面四种 |

## 五、错误码与提示语

| 场景 | 文案 | 出口 |
| --- | --- | --- |
| 商品不存在/已下架 | 商品不存在或已下架 | 404 错误页 / `?error=` |
| 库存为 0 仍提交 | 该商品已售罄，暂时无法提交意向 | `?error=` |
| 同一买家重复下单 | 你已对该商品提交过意向，请在卖家处理后再次购买 | `?error=` |
| 口令码无效 | 口令码无效，或该意向不可撤销（仅排队中的意向可撤销） | `?error=` |
| 提交成功 | 购买意向已提交，等待卖家确认。可在「我的订单」查看已有结果的订单。 | `?msg=` |
| 确认交易 | 已确认交易，商品进入「交易中」，其他买家暂时无法下单 | `?msg=` |
| 交易成功 | 已标记交易成功，库存扣减 1 件 | `?msg=` |
| 交易失败（作废） | 已标记交易失败并作废该买家的意向 | `?msg=` |
| 交易失败（塞回） | 已标记交易失败，该买家已塞回队尾重新排队 | `?msg=` |
| 库存不足无法成交 | 该商品库存不足，无法标记交易成功 | `?error=`（事务回滚） |

## 六、联调检查清单（本模块 10 项）

| # | 检查项 | 预期 |
| --- | --- | --- |
| 1 | 未登录点「登录后购买」 | 302 到 `/buyer/login?redirect=/products/{id}`，登录后回原商品 |
| 2 | 同一买家对同一商品提交两次 | 第二次被拒绝，提示「你已对该商品提交过意向」 |
| 3 | 两个人先后对同一商品提交 | 队列页按提交时间升序，先提交的在前 |
| 4 | 卖家确认非队首的单 | 拒绝，提示只能确认队首 |
| 5 | 确认交易后商品状态 | 列表页不再出现，详情页显示「交易中」，其他人无法下单 |
| 6 | 交易成功 | 订单进「我的订单」，结果=成功，库存减 1，商品回到在售 |
| 7 | 交易失败并作废 | 订单进「我的订单」，结果=失败且带原因，库存不变，商品回到在售 |
| 8 | 交易失败并塞回 | 该买家回到队尾，刷新后 `pending` 时间变新，队列排到最后 |
| 9 | 库存扣到 0 | 剩余排队单批量变「失败」，原因=商品库存已售罄 |
| 10 | 卖家查看客户详情 | 购买历史列出该客户所有已结束订单，未结束的不出现 |

## 七、已知降级（商品模块字段未到位时）

| 现象 | 原因 | 字段到位后的行为 |
| --- | --- | --- |
| 库存显示「不限」，成交不扣数 | `product.stock` 列不存在 | 自动改读库存，成交原子扣减 1 件，扣到 0 触发批量失败 |
| 详情页只有一张占位图 | `product_image` 表不存在 | 自动改读图集，按 `sort_no` 排序，第一张为主图 |
| 分类筛选只有一级 | `category.parent_id` 不存在 | 自动切换为两级树 |

三处均由 `SchemaCapability` 启动时探测列/表是否存在决定，**不需要改代码**。

## 二、技术问题与解决方法

### 1. 连接池默认配置会让 SQLite 直接报错

**问题：** SQLite 是单文件库，同一时刻只允许一个写事务。Spring Boot 默认给 10 个连接，三个人本地同时点页面、或者一个人快速连点提交，多个连接抢写锁就会抛 `SQLITE_BUSY`。这个错误出现的时机很随机，本地单点测试几乎复现不了，一到联调就冒出来。

**处理方法：** 把 Hikari 连接池固定为 1 个连接（`maximum-pool-size: 1`），让所有写请求在连接这一层就排好队，交给 SQLite 时永远是串行的。同时用 `connection-init-sql: PRAGMA foreign_keys = ON` 保证每个连接都打开外键——SQLite 的外键开关是**按连接**生效的，不随数据库文件保存，不显式打开等于没约束。日志模式改成 WAL 并写进建表脚本，让读操作不被写事务挡住。

**代价与判断：** 连接池为 1 意味着并发读也要排队。我按课程演示的规模（同时 3~5 人操作、几百条数据）评估过，这个代价可以接受；如果以后要上多用户真实场景，正确做法是换 MySQL 或 PostgreSQL，而不是把连接数调大——SQLite 的写锁在数据库层面，调池子治不了根。

### 2. 同一套异常，页面和接口需要两种输出

**问题：** 后台页面是服务端渲染的，出错应该显示一张友好的错误页；但以后接 ajax 的接口如果也返回错误页 HTML，前端 `fetch` 拿到的就是一段 `<html>`，解析 JSON 时抛 `Unexpected token <`，报错信息完全指不到真正原因。同理，登录拦截对页面应该 302 跳登录页，对接口应该返回 401 加 JSON。

**处理方法：** 在 `RequestUtils` 里只写一处判定：URI 以 `/api/` 开头、或带 `X-Requested-With`、或 `Accept` 含 `application/json`，就按接口处理，其余按页面处理。全局异常处理和登录拦截器都调用这同一个方法，保证两处口径不会走岔。

这里我一开始写的是两个 `@ControllerAdvice`，一个管页面一个管 JSON。调试时发现 `@RestController` 本身带 `@Controller` 元注解，两个 Advice 会同时命中同一个 Controller，最终谁生效取决于 `@Order`，行为不可预期。改成「一个 Advice + 按 URI 分流」之后规则就唯一了，也好跟组员解释。

**顺带修掉的一个坑：** 我原本用「业务错误码 ÷ 100」反推 HTTP 状态码，但 `40103 原密码错误` 的 HTTP 状态实际是 400，除出来是 401，接口返回的状态码和文档对不上。后来改成由错误码枚举显式携带 `httpStatus`，不再反推。

### 3. 建表脚本必须能反复执行

**问题：** 建表脚本随应用启动自动执行。如果只写 `CREATE TABLE`，第二次启动就报「表已存在」，应用起不来；如果种子数据用普通 `INSERT`，每重启一次就多插一条账号，最后库里出现一堆 `admin`。而「删库重来」是最容易在演示前手忙脚乱的操作。

**处理方法：** 建表全部改 `CREATE TABLE IF NOT EXISTS`、建索引全部 `IF NOT EXISTS`、种子数据用 `INSERT OR IGNORE` 并按固定主键插入。这样重复执行既不报错也不重复写数据。

**一个容易忽略的好处：** 因为种子账号是按主键 1 `INSERT OR IGNORE`，用户改过密码之后重启应用不会被重置回 `admin12345`——这正是演示前最怕发生的事。我为此专门写了测试，把建表脚本连跑三遍，断言表结构不变、账号仍是 1 条、分类仍是 5 条。

## 三、我的收获

这次最大的变化不是学会了 Spring Boot，而是明白了**「我一个人能跑」和「三个人能一起跑」是两件事**。迭代 1 我写 Python 时，接口怎么定、返回什么全在自己脑子里，改一下也没人受影响；这次一开始就三个人并行，如果我不先把实体、Mapper、返回体、接口契约定下来，他们只能等着我。

第二个收获是关于验收标准。以前我觉得「功能能点通」就算完成，这次每条任务都有明确的验收标准（比如「schema.sql 可重复执行不报错」），我才发现如果不写成测试，这类要求根本没法证明——我现在说它不报错，评审时老师凭什么信？把它变成一条断言，就成了证据。

第三个是踩坑的方式变了。`SQLITE_BUSY` 和「接口返回登录页 HTML」这类问题，单元测试和单人点页面都遇不到，只在特定组合下出现。我开始习惯先问「这个决定的代价是什么」——连接池调成 1 会牺牲并发，但换来了确定性和不报错，在课程规模下这笔账是划算的。

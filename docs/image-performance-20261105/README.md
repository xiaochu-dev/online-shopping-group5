# 商品图片性能优化

基准版本：`09afc98`。环境：Windows、Temurin JDK17.0.21+9、Maven Wrapper3.9.9。日期：2026-11-05。

## 改动

- 原图字节与数据库原图路径保持不变。上传时复用已解码图片，生成最长边400像素、质量0.80的JPEG缩略图，不放大小图；透明区域在缩略图中合成白底，原图透明度保留。
- 小图保存为 `uploads/thumbs/<原文件名>.jpg`。只有缩略图比原图小时才保存，避免小文件变大。沿用JDK自带ImageIO，没有新增图片库或数据库字段。
- 商品列表、商品管理列表和卖家商品列表使用缩略图；每个列表第一张图正常加载，其他图片标记懒加载，显式设置显示尺寸。
- 详情主图仍使用原图；缩略图栏使用小图，点击后通过独立的原图地址切换主图，避免误把小图放大。非首屏缩略图使用懒加载。
- 旧商品、占位图、没有缩略图的文件回退使用原地址，不在读请求中生成图片，不批量改写旧数据。
- 缩略图与原图一起加入事务失败清理；静态资源目录与上传目录统一读取 `shop.product.upload-dir`，支持独立演示/测试目录。

## 实测结果

使用同一组9张Keychron官网商品图，哈希在[before.json](before.json)和[after.json](after.json)中逐张对应。原始图源为[Keychron K8商品页](https://www.keychron.com/products/keychron-k8-tenkeyless-wireless-mechanical-keyboard)，非本人实拍。两个版本顺序运行相同基准代码，每版预热发布3次，再测12次，每次发布9张图。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 默认列表12张封面图片响应体合计 | 757,980 B | 178,860 B | 减少76.40% |
| 九图详情页全部图片响应体合计 | 739,690 B | 213,199 B | 减少71.18% |
| 15次九图发布的图片磁盘增量 | 11,095,350 B | 13,345,860 B | 增加20.28% |
| 九图发布服务耗时中位数 | 1717.50 ms | 1849.33 ms | 增加131.84 ms（7.68%） |
| 九图发布服务耗时P95 | 1795.61 ms | 1966.42 ms | 增加9.51% |

字节数由实际渲染HTML提取图片地址，再通过MockMvc读取每个不同地址的静态资源响应体求和；全部请求成功。列表12件商品使用相同第一张样本作为封面，但上传文件地址各不相同。详情包括一张原图主图和九张缩略图；优化前同一原图重复引用只算一次。数据是完整图片集合的HTTP响应体字节，不含协议头，也不是实际浏览器首屏流量或加载时长。

懒加载的收益另外体现为列表12张封面中11张带 `loading="lazy"`，详情缩略图按需加载；浏览器何时触发下载由其可视区域与预取策略决定，本表没有把这些图片计成零流量。基准直接调用真实发布服务，耗时包含校验、图片处理、文件写入及数据库提交，不包含客户端网络上传。P95基于12个样本，作为本机对比记录；不作跨硬件或生产吞吐量承诺。

## 验证与复现

`ProductImagePerformanceTest` 验证原图字节不变、缩略图尺寸/大小、配置目录HTTP访问、列表懒加载、详情原图切换标记、旧图回退、数据库回滚时两种图片共同清理、无效批次不写文件、小图不放大与透明图处理。

普通回归：

本次JDK17实际执行136项（团队基准129项＋图片新增7项），失败0、错误0、跳过0；基准测试单独显式运行通过。浏览器实际核对列表小图400像素，点击详情第二张缩略图后主图切换到对应1200×1200原图，均成功加载。

```powershell
.\mvnw.cmd test
```

基准需显式指定，不纳入日常自动测试。样本目录应包含相同9张JPG：

```powershell
.\mvnw.cmd test -Dtest=ImagePerformanceBenchmark "-Dimage.perf.dir=C:\path\to\photos"
```

产出 `target/image-benchmark.json`。对基准09afc98应用同一基准测试文件并运行，再与优化版比较。基准使用工作树自己的 `uploads/` 和UUID测试库，不操作原始课程数据库。对比原始统计见[comparison.csv](comparison.csv)。
